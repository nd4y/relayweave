# Безопасность и границы аудита

[English](security.md) | **Русский**

Явно выбирайте частные интерфейсы LAN/NetBird; привязка по умолчанию - 127.0.0.1. Единственный администратор использует ADMIN_PASSWORD. Сеансовые cookie, проверки CSRF/origin, оптимистические версии и устойчиво сохраняемые операции защищают изменения настроек. Публикуйте интерфейс через HTTPS и задавайте COOKIE_SECURE соответственно. Необязательные пароли HTTP/SOCKS-клиентов являются отдельными учётными данными точек входа.

Загрузка источников проверяет разрешённые DNS-адреса, ограничивает размер ответа и удаляет учётные данные/заголовки устройства при перенаправлении на другой хост. Частные адреса источников требуют явного разрешения. Независимые проверки ядер не передают заголовки подписки или cookie администратора. Секреты шифруются при хранении защищённым локальным ключом. Храните DATA_ROOT/env в закрытом доступе; шифрование резервной копии не защищает скомпрометированный работающий хост.

Воркеры используют mTLS и зашифрованные контрольные точки восстановления/отзыва. Неудачная выкатка сохраняет разрешённые последние рабочие пути, не расширяя ограничения более нового отзыва. Команды адресованы конкретному воркеру; поколения, повторы и дубли результатов обрабатываются явно. Контейнеры не получают Docker socket, работают без root с файловой системой только для чтения и имеют конечные бюджеты CPU/памяти/PID/дескрипторов/UDP/процессов/замеров.

Проверка происхождения исполняемых файлов сверяет разрешённый источник GitHub Release, архитектуру, SHA-256 архива, SHA-256 извлечённого бинарного файла и точную версию Xray. Это не подтверждает независимую подпись upstream или отсутствие уязвимостей. Разрешение сборки означает доверие исполняемому коду; проверяйте репозиторий и байты выпуска. Проверка digest при запуске обнаруживает изменение файла до старта процесса.

## Видимость URL подписки

В карточке подписки и редакторе источника справа от поля URL есть кнопка с глазом.
Обычные ответы списка и подробностей источника сохраняют маскировку. Только явное
нажатие администратора вызывает `POST /api/v1/sources/{id}/reveal-url`, защищённый
существующими проверками сеанса, same-origin и CSRF. Ответ содержит только URL
источника, без заголовков устройства и других секретов, и запрещает кэширование
через private no-store.

Полученный URL хранится только в памяти открытого поля и очищается при скрытии,
через 60 секунд, при уходе страницы в фон и при изменении источника/версии.
Поздний ответ не восстанавливает адрес после закрытия поля. Показ сохранённого URL
не меняет редактируемое значение и не сохраняет учётные данные повторно. Новый
введённый URL показывается и скрывается локально. Автоматической записи в буфер
обмена или хранилище браузера нет. Демонстрация экрана и инструменты разработчика
всё ещё могут раскрыть явно показанный URL; автоматическое скрытие защищает
представление, а не скомпрометированный браузер или сеанс администратора.

## Результаты аудита и оставшиеся проверки

Компилятор приложения закреплён на Go 1.27.2. Зафиксированная проверка исходников приложения через govulncheck не обнаружила достижимых уязвимостей. Полный npm audit фронтенда, включая dev-зависимости, не обнаружил уязвимостей 2026-10-19. Результаты относятся только к проверенным снимкам.

Фронтенд перешёл со старой ветки nginx 1.29 на официальный стабильный nginx 1.30.6, закреплённый многоархитектурным digest. Этот выпуск включает исправления upstream от 2026-10-14. Базовые образы сборки/исполнения Node, Go и distroless также имеют явные digest. Сканирование образов и браузерные регрессионные проверки должны использовать именно итоговые образы.

Необязательный официальный Xray 26.9.30 собран Go 1.27.1. Сканирование бинарного файла сообщило о 14 уязвимостях, включая старые зависимости стандартной библиотеки/x/net/compress. Этот стенд проверяет совместимость нескольких версий и не является рекомендуемым ядром для production по умолчанию. Официальное происхождение не отменяет проверку безопасности старой версии.

Включённый Xray 26.10.17 использует Go 1.27.2 и обновлённые зависимости. Сканирование бинарного файла без отладочных символов консервативно сообщило об уязвимости неподдерживаемого OpenPGP GO-2026-5932. Последующий анализ исходников govulncheck для точного upstream-коммита 92ccc939aaf4f8965f369cf0b142e005aeaa11d5, точки входа ./main и Go 1.27.2 не обнаружил достижимых уязвимостей или затронутых импортируемых пакетов. OpenPGP остаётся только в требуемом модуле, затронутый пакет которого не импортируется. Это разрешает конкретное предупреждение о достижимости, а не скрывает результат сканера. Каждое другое ядро/сборка требует собственной оценки. Итоговая проверка также должна зафиксировать аудит образов и базовых компонентов.

Отчёты upstream: [гонка Go HTTP/2 HPACK](https://pkg.go.dev/vuln/GO-2026-6617), [неподдерживаемый OpenPGP](https://pkg.go.dev/vuln/GO-2026-5932), [точные исходники встроенного Xray](https://github.com/XTLS/Xray-core/tree/92ccc939aaf4f8965f369cf0b142e005aeaa11d5).
