# Диагностика маршрута CONNECT

[English](connect-diagnostics.md) | **Русский**

Воркер может возвращать выбранные маршрут, профиль и ISP в успешном ответе HTTP
CONNECT. Это связывает зависшую передачу клиента с фактическим маршрутом без
расшифровки TLS и изменения механизма передачи данных туннеля.

По умолчанию диагностика отключена. Для доверенного диагностического клиента
добавьте переменную окружения в сервис воркера вашего развёртывания:

```yaml
environment:
  WORKER_CONNECT_DIAGNOSTICS_CIDRS: "192.0.2.10/32,2001:db8::10/128"
```

Замените адреса из примера адресами источника клиента. Переменная читается один
раз при запуске воркера. Для отключения удалите её или задайте пустую строку и
пересоздайте воркер. Пересоздание прерывает его текущие соединения, поэтому
сохраните прежние конфигурацию развёртывания и образ для отката.

Список допуска проверяет фактического TCP-клиента. Заголовки `Forwarded`,
`X-Forwarded-For` и другие заголовки запроса не предоставляют доступ. Если
обратный прокси завершает клиентское соединение, проверяется адрес этого прокси:
его разрешение откроет диагностику всем прошедшим аутентификацию клиентам за ним.
Для ограничения отдельными клиентами используйте прямой listener воркера.
Обычные ограничения listener и аутентификация продолжают действовать. Любой
неверный CIDR или более 32 записей отключают весь диагностический список.

Разрешённый успешный ответ содержит:

```text
X-RelayWeave-Route-ID: <selected route ID>
X-RelayWeave-Profile-ID: <selected profile ID>
X-RelayWeave-ISP: <selected egress ID>
```

Возвращаются только идентификаторы ограниченной длины, без адреса назначения,
URL, идентичности клиента и реквизитов подписки. Неверные или отсутствующие
идентификаторы исключают все диагностические заголовки. Для остальных клиентов
сохраняются прежние байты ответа CONNECT. SOCKS и обычные HTTP-ответы не меняются.

Для контролируемого публичного тестового адреса `curl --dump-header headers.txt`
сохраняет ответ CONNECT прокси перед ответом сервера. Для каждой параллельной
передачи нужен отдельный файл заголовков. Повторно используемое соединение может
не иметь нового ответа CONNECT: сопоставляйте его с исходным соединением, не
приписывая ему новый маршрут. Ошибки до успешного CONNECT по-прежнему требуют
отдельной диагностики воркера. Заголовки указывают выбранный путь, а не причину
ошибки. Не публикуйте захваты с закрытых адресов или адресов с аутентификацией.
