# MeTube: параллельные загрузки со стабильным upstream для каждого файла

[English](README.md) | **Русский**

Общий прокси RelayWeave балансирует соединения. Некоторым запросам
медиа/CDN нужен один и тот же выход на протяжении всего извлечения и загрузки.
Для таких запросов используйте аутентифицированные внутренние слушатели,
опирающиеся на независимые группы серверных IP, и интеграцию `sitecustomize.py`
только для чтения из этого каталога.

Хук выбирает здоровый путь с наименьшей активной нагрузкой один раз на
извлечение метаданных или загрузку. Он устанавливает путь до того, как MeTube
устанавливает свою существующую защиту сокета. Каждый последующий запрос в этом
экземпляре yt-dlp сохраняет его, включая aria2 и параллельные фрагменты HLS.
Независимые файлы могут использовать разные пути. Уже установленное
TCP-соединение никогда не переносится.

Каждая политика пути использует пул для одной независимо проверенной группы
серверных хостов/IP, детерминированный выбор `fallback`, один активный маршрут и
один резерв. Перед добавлением пути проверьте совместимость источника, а также
общую конечную точку здоровья. Эти пулы следуют за обновлением подписки для
настроенного имени хоста; они не являются автоматическим обнаружением каждого
будущего имени хоста в подписке. Общий IP - лишь консервативная подсказка о
ёмкости; фактическую согласованность выхода всё ещё нужно проверять вживую.
Предпочитайте хосты с согласованным исходящим трафиком приложения.

Политики могут иметь HTTPS-пробу для конкретной цели без общего запасного
варианта. Worker оценивает эту цель отдельно для каждой политики, поэтому в
остальном здоровое ядро может быть отклонено для этой нагрузки, не попадая в
карантин для других клиентов. Сам HTTP CONNECT не может проверять зашифрованные
ошибки приложения.

Конфигурация в официальном контейнере MeTube:

```yaml
environment:
  PYTHONPATH: /opt/relayweave:/app/app
  RELAYWEAVE_DOWNLOAD_PATHS: '[{"port":8083,"policy_id":"path-a"},{"port":8084,"policy_id":"path-b"}]'
volumes:
  - /path/to/public/integration:/opt/relayweave:ro
```

`YTDL_OPTIONS.proxy` и `HTTP_PROXY` указывают на аутентифицированный внутренний
базовый слушатель `relayweave-proxy:8082`; храните фактический пароль в
защищённой конфигурации домашнего хоста. Каждый выбранный порт должен
использовать одни и те же учётные данные. Привяжите доступ к существующей
приватной подсети Docker, требуйте аутентификацию и не публикуйте ни один из
дополнительных портов на хосте или в Traefik. Интеграция переписывает только
этот конкретный базовый прокси; явно заданные другие прокси сохраняются.

Оставляйте `MAX_CONCURRENT_DOWNLOADS=4`. Используйте опции aria2 HTTP/HTTPS
`-x8 -s8 -j1 -k1M` и yt-dlp `concurrent_fragment_downloads=8` для нативного HLS.
Один лишь лимит aria2 не распараллеливает нативный HLS. Эти значения являются
верхними границами, а не гарантированным числом одновременно полезных
соединений.

Статус маршрутов запрашивается напрямую с существующего приватного порта статуса
worker, с тайм-аутом две секунды, кэшем одна секунда и не более пяти секунд
кэшированного запасного варианта. Отсутствие здорового пути приводит к понятной
ошибке, а не к непроверенному прямому соединению. Общие IP между путями
учитываются в эвристике выбора по суммарной нагрузке. Нездоровый путь
исключается для новой работы; существующие запросы приложения не воспроизводятся
прозрачно под другими идентичностями. Повтор всей задачи остаётся заботой
приложения. Здоровье цели, идентичность источника и полный выходной медиафайл
должны проверяться в живых тестах; одного успешного запроса главной страницы
недостаточно.

Эта небольшая интеграция зависит от `dl_formats.get_opts` в MeTube и конструктора
yt-dlp. После обновления MeTube проверьте `sitecustomize.HOOK_ACTIVE`, обёрнутую
функцию и реальную загрузку, прежде чем объявлять совместимость. Используйте
точно развёрнутый образ и сохраняйте контрольную точку Compose/конфигурации для
отката. Хук не записывает исходный URL, учётные данные, имя файла или полезную
нагрузку.

`test_routing.py` проверяет контракт выбора, используя только синтетические
модули и статус. Запускайте его на сборочном хосте. Тесты с реальными
источниками и приватные манифесты остаются на домашнем хосте; никогда не
загружайте их на сборочный сервер или в публичный репозиторий.
