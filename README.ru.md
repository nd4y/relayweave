# RelayWeave

Балансировка по паре «прокси + ISP», настройка исходящих адресов и ограничения
`sendThrough` описаны в [руководстве DualWAN](docs/dualwan.md).

Опциональный [модуль телеметрии роутеров](docs/router-integrations.md) поддерживает
MikroTik API-SSL только для чтения. Данные роутера дополняют автоматический выбор
профилей и весов; без роутера или при потере телеметрии работает автономная автоматика.

[English](README.md) | **Русский**

**Your routes. In harmony.**

Прокси-платформа для домашней сети и контейнеров: объединяет подписки, запускает
несколько версий Xray и распределяет новые соединения между доступными путями,
предпочитая разные серверные IP общему балансиру.

![Карта трафика на синтетических демонстрационных данных](docs/images/traffic-map.png)

## Возможности

- Раздельные управляющий сервис, воркеры и интерфейс React/Material UI; Docker Compose.
- HTTP-прокси и SOCKS5 TCP/UDP, необязательная аутентификация на каждом входе.
- Один администратор: пароль в переменной окружения, без имени пользователя.
- Несколько подписок, агрегаты, пулы профилей и политики маршрутизации.
- Xray26.10.17 в образе; дополнительные одобренные версии и сборки загружаются
  по запросу и могут работать одновременно. Другие движки расширяют интерфейс адаптеров.
- Проверки доступности, ограниченные повторы, восстановление последней рабочей
  конфигурации и завершение существующих соединений на прежних путях.
- [Автоматическое обновление адресов подписок](docs/subscription-rollover.md):
  проверка новых прокси, плавный перевод новых соединений и сохранение разрешённых
  TCP/UDP-сессий на прежнем Xray. Изменения ключей и TLS требуют проверки.
- Предпочтение разных IP; пересекающиеся наборы адресов объединяются в общую группу.
- Карта React Flow со встроенной в браузер ELK: раскрытие профилей, реальные причины
  выбора маршрута, графики скорости/RTT, полный экран и сворачиваемые фильтры.
- Метрики Prometheus, структурированные логи, необязательный Loki и дашборды для внешней Grafana.
- Экспорт подключения для Throne и аналогов, ограниченные и отзываемые подписки доступа.

## Запуск

Нужны Linux Docker Engine и Docker Compose. Сборку выполняйте на машине с достаточным
объёмом памяти и диска. Образы поддерживают amd64 и arm64.

```sh
git clone https://github.com/nd4y/relayweave.git
cd relayweave
cp .env.example .env
chmod 600 .env
# Задайте разные случайные ADMIN_PASSWORD и DATABASE_PASSWORD.
# Для DATABASE_PASSWORD используйте URL-безопасные буквы и цифры.
docker compose config --quiet
docker compose build
docker compose up -d --wait --wait-timeout 600
```

Откройте `http://127.0.0.1:18443`, введите пароль администратора, добавьте подписки,
создайте пулы, политики и входы. Просмотрите план и примените конфигурацию.
Свежая установка не содержит ваших подписок. В публичном Compose используется bridge.

| Назначение | Порт по умолчанию |
| --- | --- |
| Интерфейс/API | 18443/TCP |
| HTTP | 18080/TCP,18081/TCP |
| SOCKS5 | 11080/TCP,11081/TCP |
| Релей UDP SOCKS5 | 31000-31255/UDP |

Порты хоста и контейнера совпадают. Для доступа из LAN/VPN согласованно задайте
BIND_IP и PROXY_ADVERTISE_IP; разрешайте подключения только доверенным устройствам.
HTTP обслуживает TCP. Для UDP клиент SOCKS5 должен поддерживать UDP ASSOCIATE;
фрагментированные датаграммы SOCKS не поддерживаются. Для HTTPS-интерфейса нужен
обратный прокси и COOKIE_SECURE=true.

## Мониторинг

Встроенного сервиса Grafana нет. Импортируйте дашборды из
`observability/grafana/dashboards` в свою Grafana и подключите Prometheus.
Чтобы включить ссылку на неё в интерфейсе, задайте GRAFANA_URL перед сборкой.
Необязательные Prometheus и Loki запускаются командой:

```sh
docker compose --profile observability up -d
```

Для этого Loki задайте LOKI_URL=http://loki:3100/loki/api/v1/push в .env и
пересоздайте control-plane/worker. Без Loki логи доступны через Docker.

## Ограничения

Балансируются новые соединения. Один уже установленный TCP-поток остаётся на
своём пути; объединения его скорости через несколько прокси или провайдеров нет.
Общий серверный IP служит консервативным признаком общего ресурса, не доказывает
выходной IP или независимую пропускную способность. Host networking не гарантирует ускорения.

Скорость на карте считается по приросту счётчиков. RTT - сглаженная оценка времени
открытия соединения адаптером ядра; она может отражать локальный этап и не равна
сквозной задержке до сайта. История ограничена последними60секундами с открытия карты.
Пропуски измерений и сбросы счётчиков разрывают линии. Содержимое HTTPS, приложения
и идентичность клиентов по такой телеметрии не определяются.

Проект активно развивается и пока имеет статус прототипа. См. [границы безопасности](docs/security.md)
и [проверки](docs/validation.md). Kubernetes/Helm и многопутевая передача одного потока
в эту версию не входят. Не публикуйте незащищённый прокси в интернете.

## Разработка

Go1.27.2 и Node26 закреплены в Dockerfile, зависимости и SHA-256 артефактов - в
lock-файлах. `tools/check-buildhost.sh` запускает проверки на сборочном сервере.
Браузерные сценарии находятся в `web/tests` и используют отдельный синтетический
стенд. Производственные подписки для них не нужны. См. [CONTRIBUTING](CONTRIBUTING.md).

Исходный код проекта: Apache-2.0. Компоненты третьих сторон сохраняют свои лицензии;
см. [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES.md).
